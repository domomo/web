# 유료 글 판매와 구매 기록 설계

## 목적과 합의된 범위

브런치처럼 글을 읽는 사이트에서 작성자가 글을 유료 상품으로 등록하고 독자가 구매 기록을 남겨 전체 글을 읽을 수 있게 한다. 기존 글 목록, 분야 필터, 페이지네이션, 상세 조회는 유지한다.

- 유료 글 구매는 포트원 V2를 통해 결제하고, 서버가 포트원 결제 내역을 조회해 상태와 금액을 확인한 뒤 구매 권한을 기록한다.
- 유료 글은 제목, 작성자, 분야, 무료 미리보기, 가격을 공개하고 본문 전체는 작성자 또는 구매자에게만 반환한다.
- 무료 글은 현재처럼 누구나 전체 내용을 읽는다.
- 기존 데이터에는 작성자 정보가 없으므로 기존 글은 무료로 유지한다. 새 유료 글은 로그인 계정과 작성자를 연결한다.
- 새 글 작성 화면에서 무료 글 또는 가격을 정한 유료 글을 등록한다. 현재 없는 글 수정·판매 설정 화면은 추가하지 않는다.
- 환불, 판매자 정산, 구매 취소, 구독, 리뷰/댓글은 범위 밖이다.

## 현재 구조

- FastAPI 글 API: `app/api/routers/board.py`; SQLAlchemy 모델: `app/models/board.py`; 응답 스키마: `app/schemas/board.py`.
- 로그인 사용자는 HttpOnly `EN_AT` JWT 쿠키를 받는다. 이메일 계정은 토큰 subject에 이메일, 카카오 계정은 `kakao:<id>`를 사용한다.
- SQLite 스키마 보정은 `app/db/database.py`에서 수행하고, 서버 시작 시 `app/main.py`가 테이블 생성과 마이그레이션 함수를 호출한다.
- Vue 글 목록/작성/상세는 `frontend/src/pages/`와 `frontend/src/api.js`에 있다. FastAPI OpenAPI를 API 계약 기준으로 사용하며 저장소에 기존 서비스용 Postman collection은 없다.
- 현재 작업 트리에 이미 사용자 변경이 있다. 이를 덮어쓰거나 커밋하지 않는다. 구현은 이 작업 트리의 현재 상태를 재현한 두 개의 독립 Git worktree에서 진행하고, 각 에이전트 변경만 소유 영역별로 추려 통합한다.

## 데이터 모델

### Board

- `author_idx`: `user.idx` 참조, nullable. 기존 글은 NULL 유지.
- `preview`: nullable 문자열. 무료 글은 NULL. 유료 글은 공백이 아닌 무료 공개 미리보기를 저장.
- `sale_price`: nullable 정수(KRW). NULL은 무료, 양수는 판매 글. 0 이하 가격은 거부.
- 기존 `title`, `contents`, `category`, `idx` 의미는 유지한다.

새 유료 글 작성 요청은 `title`, `contents`, `category`, `sale_price`, `preview`를 받는다. 무료 글 작성 요청은 현재 계약처럼 `title`, `contents`, `category`를 받는다. 판매 가격을 지정한 요청만 인증이 필요하며, 인증 사용자의 `author_idx`를 서버가 지정한다. 요청 body에서 작성자 ID를 받지 않는다.

### Purchase

- 구매 행은 구매자 ID, 글 ID, 구매 당시 가격(KRW), 생성 시각을 저장한다.
- `(buyer_idx, board_idx)`에 unique 제약을 둬 같은 사용자가 같은 글을 중복 구매하지 않게 한다.
- 가격은 구매 당시 값으로 보존한다. 이번 범위에는 가격 변경 UI가 없지만, 구매 기록의 의미를 안정적으로 유지한다.
- 구매 API는 데이터베이스 트랜잭션에서 상품 유료 여부 확인, 작성자 본인 구매 방지, 구매 행 생성을 처리한다. 중복 호출은 기존 구매를 반환해 재시도에 안전하게 한다.

## 인증과 권한

- 백엔드는 `EN_AT` 서명과 만료를 검증하고 이메일 또는 `kakao_user_id`로 `User`를 찾는 공통 현재 사용자 의존성을 제공한다.
- 무료 글 쓰기는 기존 익명 동작을 유지한다. 유료 글 게시와 구매는 로그인 필수이며 누락/무효 쿠키는 401이다.
- 판매자 본인은 자신의 글을 구매할 수 없다(409). 존재하지 않는 글 또는 판매 대상이 아닌 글 구매 요청은 404/409로 명확히 거절한다.
- 글 목록과 상세 조회는 공개 상태를 유지한다. 유료 글의 조회 응답에는 `preview`, `sale_price`, 판매 여부, 작성자 표시명, `is_author`, `has_purchased`를 포함하고, 권한이 없으면 `contents: null`, 권한이 있으면 전체 `contents`를 반환한다.
- 전체 글 내용을 응답에서 감추는 검사는 프런트엔드가 아니라 서버에서 수행한다.
- 작성자 이름만 노출하며 이메일, 카카오 ID, 토큰 subject는 공개하지 않는다.

## API 계약

기존 경로와 pagination/category 매개변수는 유지한다.

### `POST /api/board/write`

- 기존 무료 글 body와 응답 동작을 유지한다.
- 유료 글 body는 `sale_price`(양의 정수)와 `preview`(공백 불가)를 추가로 받는다. 유료 등록 요청은 인증된 사용자가 필요하다.
- 작성 응답은 목록/상세에 필요한 판매 필드를 포함하되 구매 권한에 따라 본문을 가리지는 않는다(작성자 본인 응답).

### `GET /api/board/list`

- 기존 `offset`, `limit`, `category` 동작을 그대로 유지한다.
- 각 항목에 `author_name`, `preview`, `sale_price`, `is_for_sale`, `is_author`, `has_purchased`를 추가한다. 익명 사용자는 구매자/작성자 상태가 false다.
- 유료 항목의 `contents`에는 미리보기만 공개하거나 빈 값을 두지 않고 NULL을 반환한다. 프런트는 목록 설명에 `preview`를 사용한다.

### `GET /api/board/read/{idx}`

- 기존 상세 경로를 유지한다. 응답 필드에 판매 및 권한 정보를 추가한다.
- 무료 글, 작성자 본인, 구매자에게 전체 `contents`를 반환한다. 그 외에는 `contents: null`과 공개 미리보기를 반환한다.

### `GET /api/purchases/config`

- 공개 응답에는 브라우저 SDK에 필요한 `store_id`, `channel_key`, 설정 준비 여부만 포함한다. API Secret은 응답하지 않는다.

### `POST /api/purchases/prepare`

- 요청: `{ "board_idx": <integer> }`.
- 요청: `{ "board_idx": <integer> }`. 로그인 필요. 서버가 판매가로 포트원 주문을 만들고 `{ payment_id, board_idx, order_name, amount, currency }`를 반환한다. 이 단계에서는 열람 권한을 주지 않는다.

### `POST /api/purchases/confirm`

- 요청: `{ "payment_id": <string> }`. 로그인 필요. 서버가 포트원 결제 조회 API를 호출하고 주문 소유자, `PAID` 상태, 결제 금액, KRW 통화가 일치할 때만 구매 기록 `{ id, board_idx, price, created_at }`을 만든다. 재확인은 기존 구매 기록을 반환한다.

## 프런트엔드 동작

- 목록에는 전체/무료/유료 탭을 제공한다. 판매 글은 가격과 미리보기를 표시하고, 미구매 독자는 목록의 구매 버튼으로 포트원 결제를 시작할 수 있다.
- 글 작성 폼에 무료/유료 선택, 가격, 미리보기 입력을 둔다. 유료 선택 시 가격은 양수, 미리보기는 필수다.
- 상세 화면은 공개 미리보기와 가격을 보여주고, 미구매 독자에게 구매 버튼을 제공한다. 성공 시 상세 조회를 다시 해 전체 본문을 표시한다.
- 포트원 `@portone/browser-sdk/v2`의 `requestPayment`를 사용하며 서버의 조회 검증이 끝나기 전에는 본문 권한을 부여하지 않는다.
- 판매자와 구매자에게는 전체 글이 보이며 구매 CTA는 숨긴다. 로그인 필요 오류는 기존 로그인 화면으로 이동할 수 있게 안내한다.
- 로딩, 실패, 재시도 및 키보드 접근성을 기존 화면 패턴에 맞춘다.

## SQLite 마이그레이션과 호환성

- 기존 `board` 테이블에 `author_idx`, `preview`, `sale_price`를 nullable 열로 추가한다. 기존 행의 값은 NULL이고 기존 글은 무료로 처리된다.
- Purchase 테이블은 SQLAlchemy metadata 생성 흐름에 등록한다.
- 마이그레이션은 반복 호출에 안전해야 하며 기존 글 제목/본문/분야와 사용자 행을 보존한다.
- 기존 list/read API 경로, 필터, pagination 및 무료 글 응답의 기존 필드는 계속 유지한다. 새 응답 필드는 additive다.

## 오류와 동시 요청

- 401: 인증이 필요한 유료 글 등록/구매에 로그인 쿠키가 없거나 유효하지 않음.
- 404: 대상 글이 없음.
- 409: 무료 글 구매 또는 판매자 본인 구매.
- 422: 필수 필드, 가격, 미리보기 형식 오류.
- unique 제약 충돌 시 구매 행을 재조회해 중복 요청에 기존 성공 결과를 반환한다.
- 구매와 상세 조회가 겹쳐도 상세 조회는 DB 구매 행으로 권한을 판단한다. 브라우저 상태를 권한 근거로 삼지 않는다.

## 검증

### Backend pytest

- 기존 익명 무료 글 작성, 전체 목록/분야 필터/pagination/상세 조회 회귀.
- 이전 SQLite `board` 스키마 마이그레이션 후 기존 데이터가 무료로 읽히는지.
- 유료 글 작성의 유효 가격/미리보기/작성자 연결 및 무효/미인증 거절.
- 미구매 사용자는 본문을 받지 못하고 미리보기만 받는지, 작성자와 구매자는 본문을 받는지.
- 구매 인증, 구매 성공, 동일 구매 재시도, 본인 구매 방지, 무료 글/없는 글 거절.
- 이메일 및 카카오 계정 쿠키 subject가 올바른 사용자로 해석되는지.

### Frontend Jest

- 무료/판매 글 목록과 미리보기·가격 표기.
- 유료 글 작성 폼 검증 및 요청 payload.
- 미구매 상세의 미리보기/구매 CTA, 구매 후 상세 재조회와 본문 표시.
- 작성자/구매자 권한 상태, 인증 오류, 구매 API 오류 및 재시도.
- 기존 목록, 분야 선택, 페이지 더 보기, 무료 상세 흐름 유지.

백엔드는 전체 pytest, 프런트엔드는 전체 Jest와 production build를 확인한다. 모의 결제 조회 테스트는 서버의 검증 로직을 확인하며 실제 PG 승인 결과를 검증하지는 않는다.

## 작업 분리와 통합

- 백엔드 에이전트와 프런트엔드 에이전트는 각자 별도 Git worktree에서 작업한다.
- backend 소유 파일은 `app/` 및 `tests/`; frontend 소유 파일은 `frontend/src/` 및 프런트 테스트다. 공유 API 계약은 이 문서를 기준으로 한다.
- 양쪽 작업 전에 현재 작업 트리의 변경된 tracked 파일과 untracked 소스/설정을 각 worktree에 복사해 동일한 기준을 만든다. 기존 사용자 변경은 어느 쪽도 커밋하지 않고, 에이전트가 추가한 변경만 분리해 통합한다.
- API 계약 구현이 먼저 검증된 뒤 프런트엔드 에이전트가 그 계약에 맞춰 화면을 구현한다. 두 작업은 별 worktree를 유지하고, 최종 통합 검증은 원래 작업 트리에서 수행한다.
- worktree 경로/브랜치 생성은 사용자 변경 파일을 덮어쓰지 않으며 기존 현재 작업 디렉터리를 이동하거나 stash하지 않는다.

## 범위 밖

결제 웹훅, 결제 취소/환불, 수수료/정산, 세금계산서, 판매 분석, 글 수정/삭제, 이미지·첨부 판매, 구매 내역 화면, 다중 통화.
